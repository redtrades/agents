# Operating stack selection — solo SDVOSB deliverables business

2026-08-22. Pricing verified by web research this date. Context: PLAN-V2/V3 (Snapshot-first revenue, free weekly digest as top-of-funnel, ~10–20 outreach emails/wk, customer ceiling ~45–58, deliverables $450–1,500). Selection bias per brief: boring, cheap, replaceable. Hard constraint honored throughout: **nothing self-hosted on the Mac sits in any customer-facing path.** The Mac (Tailscale + local LLM + MLX) is the factory; everything a customer touches lives on someone else's always-on infrastructure.

## 1. Transactional / outreach email — Gmail manual, GMass only if volume grows

**Recommendation: no sequencing tool at launch.** At 10–20 personalized emails/week to a market with a ~50-customer ceiling, an Instantly-class tool is solving a problem this business is structurally forbidden from having. The PLAN-V2 economics depend on high-touch, narrow-segment outreach — mass sequencing tooling pushes toward the opposite behavior.

Launch setup: Google Workspace Business Starter ($7/user/mo annual, $8.40 monthly — already decided), SPF/DKIM/DMARC configured on the domain, Gmail templates for the 3–4 outreach variants, and a `crm/outreach.csv` in the repo (see §9) tracking sent date / follow-up date / reply status. Gmail's snooze covers follow-up timing at this volume. Reply tracking at 20/wk is reading your inbox; a local script can grep the Gmail API for thread status if that ever gets tedious.

**Upgrade trigger:** if outreach sustainably exceeds ~40–50/wk, add GMass Standard ($29.95/mo, $20.75 effective annual — 2026 pricing after their Jan 1 increase). It runs inside Gmail, does reply-detection-stops-sequence correctly, and merges from Sheets — the one Instantly-class feature that matters here, without a separate sending infrastructure to warm. Streak ($49/mo entry) is not worth it at this scale.

*(Revised 2026-08-22, PROPOSAL-0006):* this section was written for the 10–20/wk world; `sop/PLAN-V4.md` §4 later raised the ramp ceiling to 100–200/wk without reconciling it here. **At the §4 scale-up trigger (50/wk), move off the primary Google Workspace domain** — it also sends deliverables, invoices, and the digest, and 100–200 cold emails/wk of scraped-contact outreach risks that domain's deliverability under Google's bulk-sender rules (0.3% spam-complaint threshold). Warm a second sending domain from M1 in parallel (cheap — ~$10/yr + warm-up time) so it's ready before the trigger fires, and use GMass or equivalent on it. The primary domain never sends cold-email volume above validation level.

Why SaaS: outbound deliverability from a residential Mac is a non-starter; Google's sending reputation is the asset being rented.

## 2. Newsletter / weekly digest — Buttondown

**Recommendation: Buttondown.** Free to 100 subscribers (full-featured, not a trial), $9/mo to 1,000, $29/mo to 5,000. The decisive features for this business: markdown-native and API-first — the digest is generated by the pipeline, so "POST the rendered markdown to the API, review, send" is the correct workflow, and Buttondown is the only candidate built around it. Clean CSV export makes it replaceable.

- **Beehiiv** — free to 2,500 subscribers is the more generous free tier, and it's the fallback if growth-marketing features (referrals, recommendation network) become the strategy. But it's a web-editor-first, monetization-oriented platform; paid tier jumps to $43/mo. Wrong shape for an API-driven B2B digest.
- **Substack** — $0 forever and its network can drive discovery, but weak API (manual paste every week), no real custom-domain email identity, and a 10% cut if the digest ever monetizes. The digest is top-of-funnel for $750 Snapshots — it should live on the business's domain, not Substack's.
- **Listmonk self-hosted** — rejected on the hard constraint. The app is free, but customer-facing email delivery would depend on the Mac being up, and you'd still pay for SES and own deliverability/bounce handling. Deliverability is precisely the thing to outsource.

Setup: ~2 hrs (custom domain, DNS, archive page linked from the landing site, embed signup form).

## 3. Historic notice/award storage — SQLite in the repo

**Recommendation: SQLite, one file (or one per source), living next to the pipeline code.** Daily SAM CSVs plus USASpending pulls accumulate to single-digit GB over years — comfortably inside SQLite territory. It's zero-ops, backed up by whatever backs up the repo (plus Time Machine), trivially queryable from Python and from the local LLM tooling, and the whole "database migration" story if it ever outgrows is `pg_load` on a rainy day.

- **Local Postgres** — adds a running service, upgrades, and auth for zero benefit at one writer and one reader. Choose it only when something needs concurrent access or a web app reads the DB directly.
- **Supabase free tier** — disqualified twice over: 500MB database cap (the SAM/USASpending accumulation blows through that in weeks) and auto-pause after 7 days of inactivity. Pro at $25/mo buys nothing this pipeline needs. Supabase is for apps with users, not for a batch analytics store.

Self-host is fine and correct here: the DB is internal to the factory. Customers only ever see rendered deliverables. Effort: none beyond what the pipeline already implies.

## 4. Vector DB / semantic memory — defer; the honest answer is "not yet"

**Recommendation: don't build a vector layer now.** This is the one function where the right answer to "which tool" is "the question is premature":

- Federal notices are structured, keyword-dense documents. Retrieval at this scale is served by **SQLite FTS5 (BM25) plus structured filters** — NAICS, agency, set-aside code, date, place of performance — which the SQLite store from §3 gives you for free. "Find sources sought like this one" is mostly a filter query with a keyword search on top.
- Past deliverables number in the dozens for the first year. Semantic search over dozens of documents is grep with extra steps.
- The failure mode of building it now: an embedding pipeline to maintain, re-embedding on model changes, and a second index to keep consistent with the DB — before any retrieval need has ever missed.

**When it does trigger** (corpus in the tens of thousands of notices *and* FTS5 demonstrably missing relevant matches, e.g. for cross-vocabulary similarity): the pick is **sqlite-vec** — a loadable extension inside the same SQLite file, embeddings generated locally via MLX (bge-small or similar), zero new services, zero cost. **LanceDB** is the step up if vectors ever number in the millions (they won't at this business's scale). **Chroma** adds a client-server process for no advantage here. All internal-only, so self-hosting is unconstrained.

Cost: $0 now and later. Effort: 0 now; roughly a day when triggered.

## 5. Landing page + domain — static site on Cloudflare Pages

**Recommendation: Cloudflare Pages (free plan) with a static site generator (Astro or even hand-rolled HTML), domain at Cloudflare Registrar (~$10.50/yr at cost).** This wins on every stated need:

- **SEO for "sources sought response" queries** — needs real multi-page content (product pages, a few genuinely useful articles, sample Snapshot pages) with full control of markup, sitemaps, and speed. Static on Cloudflare's edge is the strongest technical SEO baseline available. Carrd is one-page-oriented and SEO-weak; that alone disqualifies it despite the $19/yr price. Framer does multi-page well but costs $10–30/mo to remove branding and use a custom domain — recurring spend for a worse content workflow.
- **Sample downloads** — static assets on Pages (or R2 free tier if files get big). No infrastructure.
- **Credibility** — veteran-owned/SDVOSB badging, past-performance style samples, and a real domain email are content problems, not platform problems.
- **Fit with existing tooling** — Mike already has Cloudflare MCP/skills installed; the site deploys from the repo with `wrangler pages deploy` or git integration. The site content is version-controlled next to everything else. Free plan: 500 builds/mo, effectively unmetered bandwidth, 100 custom domains — no realistic limit here.

Customer-facing, but hosted on Cloudflare's edge — the Mac builds it, Cloudflare serves it. No SPOF. Effort: 1–2 days for a credible v1 (home, product/pricing, sample download, digest signup, about/veteran-owned, booking link).

## 6. Payments — Stripe Invoicing with ACH Direct Debit, cards as convenience

**Recommendation: Stripe Invoicing (Starter tier: 0.4% per paid invoice, capped at $2) with ACH Direct Debit (0.8%, capped at $5) enabled, card as secondary.** What small GovCon buyers actually do: these firms live in a Net-30, invoice-and-ACH world — their own AP runs through invoices, many have card limits or policies against card payment for services, and government-side payment culture (EFT/ACH via IPP and similar portals) shapes their habits. An invoice with ACH and card options matches how they already pay vendors; a bare checkout link reads consumer-grade.

Per-transaction math on the $450–1,500 range: ACH costs $3.60–$5.00 (cap hits at $625); card costs $13.35–$43.80 (2.9% + 30¢). Plus the 0.4%/max-$2 invoicing fee. So a $750 Snapshot paid by ACH costs ~$7 all-in vs ~$24 by card — offer both, default the invoice to ACH.

Practical setup: one Stripe account; invoice template with Net-30 terms and the order-form language (§7); a Payment Link kept as a secondary path for a buyer who wants to just pay for a Snapshot off the website. Also accept plain ACH credit (customer pushes from their bank — $0 fee to you, just reconcile manually) and even a mailed check for the occasional traditionalist; at 5–10 transactions/month, manual reconciliation is minutes.

No fixed monthly cost. Effort: ~2 hrs.

## 7. E-sign / light contracts — invoice-acceptance first, DocuSeal cloud when needed

**Recommendation: don't make signing a gate at $450–1,500.** Standard small-B2B practice at this price point: a one-page order form / terms PDF attached to (or linked from) the Stripe invoice, with "payment constitutes acceptance of these terms" language. It removes a whole step from the buying flow. (Not legal advice; worth a one-time review of the terms language by a lawyer.)

When a buyer's process demands a real signature (some GovCon firms will, reflexively): **DocuSeal cloud free tier** covers the volume (free tier on their hosted cloud; Pro is $20/mo/user if it ever doesn't). Deliberately use their *cloud*, not the self-hostable version, despite self-hosting being free — a signing link a customer opens next Tuesday must not depend on the Mac being awake. Dropbox Sign free is the fallback (limited but indefinite; $15/mo paid); full DocuSign is overkill.

Cost: $0. Effort: ~1 hr to draft the order-form template plus a DocuSeal template.

## 8. Scheduling — Cal.com free plan

**Recommendation: Cal.com free individual plan.** Unlimited event types and bookings, connects to the Google Workspace calendar, routing forms and workflows included on free (2026). Two event types: 15-min intro call (linked from outreach emails and the site) and 30-min Snapshot walkthrough (post-purchase). Do not self-host Cal.com — the booking page is customer-facing; the hosted free tier exists precisely so you don't have to. Cost: $0. Effort: ~30 min.

## 9. CRM — files in the repo

**Recommendation: markdown + CSV in the repo, git-versioned.** *(Figure corrected 2026-08-22, PROPOSAL-0001 — this section's original "~1,500 firms" was an underived stray guess; the derived figure is ~36,265 SDVOSB-certified firms total, ~38.5K firm-code slots across the 6 target NAICS, see `research/naics-selection/REPORT.md` and `sop/PLAN-V3.md` §3.)* The active pipeline is still only tens of firms/week and the customer ceiling is ~58, so this is not a CRM problem; it's two files: `crm/pipeline.csv` (firm, contact, NAICS, stage, last touch, next action, source) and `crm/notes/<firm>.md` for call notes. Advantages that actually matter here: lives next to the data pipeline (outreach targeting can be *generated* from the SQLite store into the CRM file), queryable by the local LLM stack, diffable, zero cost, zero lock-in.

- **Airtable free** — 1,000 records/base hard cap and 100 automation runs/mo; the record cap collides with any ambition to load the full VetCert-derived target list. Paid starts at $20/seat. No.
- **Notion free** — fine as a UI fallback if staring at CSVs grates; no record caps for individual use. But it splits the system of record away from the repo. Only adopt if the file-based version demonstrably fails.

Internal-only, so self-host/file-based is unconstrained. Effort: ~1 hr to set up the schema and a couple of helper scripts.

## Build order

**Phase 0 — before the first outreach email leaves (blocking):**

1. Domain registered (Cloudflare Registrar), DNS on Cloudflare.
2. Google Workspace on the domain; SPF/DKIM/DMARC verified; send a few normal emails for days rather than going 0→20 cold.
3. Landing page v1 on Cloudflare Pages — even three pages: home/credibility (veteran-owned), Snapshot product page with a sample download, digest signup. Outreach emails cite a URL; the URL must not 404.
4. Cal.com intro-call link, embedded on the site and in the email signature.
5. `crm/pipeline.csv` seeded with the first target list from the SQLite store.

**Phase 1 — before the first sale closes (days later, not blocking outreach):**

6. Stripe account + invoice template with Net-30/ACH + order-form terms PDF.
7. Buttondown wired to the signup form; first digest can ship to a 10-person list — the digest is top-of-funnel and should start accumulating immediately even if tiny.

**Phase 2 — triggered, not scheduled:**

8. DocuSeal template — first time a buyer asks for a signature.
9. GMass — if outreach volume outgrows manual.
10. sqlite-vec + MLX embeddings — if and when FTS5 retrieval demonstrably misses.
11. Postgres migration — only if something needs concurrent DB access.

The through-line: Phase 0 is one focused weekend, the fixed burn is a rounding error against a single $450 deliverable, and every component is exportable (CSV out of Buttondown, files out of everything else) — nothing here is a decision that costs more than an afternoon to reverse.
